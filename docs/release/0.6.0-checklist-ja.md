# 0.6.0 リリース手順書（クリック手順）

この手順書は、ctxjev 0.6.0 を npm に公開し、Claude Code のプラグイン配布を「リリースしたコードだけ」に固定するための、あなた（保守者）向けの手順です。上から順に行ってください。途中で何かが失敗したら、**その先に進まず**、第6節を見てください。

- 前提：PR A（ラウンド1.5の作業）が `main` にマージ済みであること。
- 所要時間の目安：全体で 30〜45 分（公開ワークフローの待ち時間を含む）。
- 費用：npm への公開は無料。公開ワークフローは Jev の API を少し使います（ライブテストと評価ゲート。これまでの実績で数セント以内）。

## 用語メモ（初出のみ）

- **PR（プルリクエスト）**：変更を `main` に取り込むための申請。GitHub の画面でマージ（取り込み）します。
- **PR B（[#9](https://github.com/x96x64/ctxjev/pull/9)）**：「0.6.0 が npm に出たあとで初めて正しくなる変更」だけを集めた PR です（MCP の設定例の版番号を 0.6.0 にする、マーケットプレイスがタグ `v0.6.0` からプラグインを配る、README の「npm はまだ 0.5.0」という注記を消す、CHANGELOG の日付）。**マージするのはあなた**です（手順1）。
- **公開ワークフロー**：GitHub Actions の「Publish to npm」。テスト・評価ゲート・版番号の検査を通ったときだけ、3つのパッケージを npm に公開し、タグ `v0.6.0` と GitHub Release を作ります。
- **マーケットプレイス**：Claude Code がプラグインを探してインストールする場所。このリポジトリの `.claude-plugin/marketplace.json` がそれです。

## 手順1：PR B をマージする

**Claude Code に頼む場合**：「PR B（#9）をマージして」と伝えてください。CI（自動検査）がすべて緑であることを確認してから、マージコミットでマージします。

**自分で行う場合**：

1. ブラウザで PR B のページを開きます：<https://github.com/x96x64/ctxjev/pull/9>
2. PR B は「Draft（下書き）」になっています。ページ下部の **「Ready for review」** ボタンをクリックします。PR A のマージ後、PR B の比較先（base）が `main` になっていることを確認します（ページ上部の「wants to merge … into `main`」。`main` でなければ Claude Code に知らせてください）。
3. ページ下部の検査の一覧で、`test (20)`、`test (22)`、`eval-harness`、`audit` の4つすべてに緑のチェック（✓）が付くまで待ちます（数分）。黄色の丸は実行中、赤い ✗ は失敗です。**赤い ✗ が1つでもあればマージしないでください**（第6節）。
4. 緑の **「Merge pull request」** ボタンの右にある ▼ をクリックし、**「Create a merge commit」** を選びます（「Squash」や「Rebase」は選ばないでください。監査文書がコミットの番号を参照しているためです）。
5. **「Merge pull request」** → **「Confirm merge」** をクリックします。
6. 「Pull request successfully merged and closed」と表示されれば完了です。**すぐに手順2へ進んでください**（手順2が終わるまでの数分間、プラグインの新規インストールはタグがまだ無いため失敗します。すでにインストール済みの人には影響ありません）。

## 手順2：公開ワークフローを実行する

1. リポジトリのページ（`https://github.com/x96x64/ctxjev`）を開き、上部の **「Actions」** タブをクリックします。
2. 左側の一覧から **「Publish to npm」** をクリックします。
3. 右側の **「Run workflow」** ボタンをクリックします。
4. 「Use workflow from」が **「Branch: main」** になっていることを確認します（`main` 以外では、公開ジョブは動かない設定です）。
5. 緑の **「Run workflow」** ボタンをクリックします。
6. 数秒後、一覧の一番上に新しい実行が表示されます。それをクリックし、全部のステップに緑のチェックが付くまで待ちます（5〜10分）。
   - 途中の「pnpm test」はライブテスト（本物の Jev を呼ぶテスト）、「Eval gate」は評価ゲート、「Check version lockstep and pins」は版番号とタグ固定の検査です。
   - 最後の「Tag and create the GitHub Release」が緑になれば、タグ `v0.6.0` と GitHub Release ができています。

## 手順3：npm に 0.6.0 が出たことを確かめる

1. ブラウザで次の3つのページを開き、それぞれページ右側の「Version」が **0.6.0** になっていることを確認します（反映に数分かかることがあります）。
   - <https://www.npmjs.com/package/ctxjev-core>
   - <https://www.npmjs.com/package/ctxjev-cli>
   - <https://www.npmjs.com/package/ctxjev-mcp>
2. GitHub のリポジトリのページで、右側の「Releases」に **v0.6.0** が表示されていることを確認します。

## 手順4：README のクイックスタートが、公開版で動くことを確かめる

公開された 0.6.0 を、何も入っていない新しいフォルダに入れて試します。Mac の「ターミナル」（Finder →「アプリケーション」→「ユーティリティ」→「ターミナル」）を開き、次を**1行ずつ**貼り付けて Enter を押してください。Node.js 22 以上が必要です（入っていなければ <https://nodejs.org> の「LTS」をインストール）。

```bash
mkdir -p ~/ctxjev-060-check && cd ~/ctxjev-060-check
curl -O https://raw.githubusercontent.com/x96x64/ctxjev/main/examples/sample-transcripts/checkout-bug.json
curl -O https://raw.githubusercontent.com/x96x64/ctxjev/main/examples/sample-transcripts/claude-code-session.jsonl
npx -y ctxjev-cli@0.6.0 --version
npx -y ctxjev-cli@0.6.0 analyze checkout-bug.json
npx -y ctxjev-cli@0.6.0 analyze claude-code-session.jsonl --goal "Fix the checkout double-charge bug."
npx -y ctxjev-cli@0.6.0 prune checkout-bug.json --out pruned.json
```

期待される結果（公開前に、公開されるものと同じパッケージで確認済み）：

- `--version` は `0.6.0` と表示されます。
- 2つの `analyze` は、API キーなしで最後まで動き、最後の行が `Scored by position alone (newest kept, like plain truncation) — no Jev call, nothing sent.` になります。1つ目の結果の行は README の「How Scoring Works」の出力例と同じです。
- `prune` は `removed 2 of 7 entries, …` と表示し、`pruned.json` ができます。
- 「`TYPESAFE_API_KEY is not set`」や「`Unknown option '--scorer'`」が出たら、古い 0.5.0 が動いています（第6節）。

README のクイックスタートどおり `npm install -g ctxjev-cli` で入れて `ctxjev --version` を試しても構いません（Mac で「EACCES」という権限のエラーが出る場合は、上の `npx` の方法で十分です）。確認が終わったら、フォルダは `rm -rf ~/ctxjev-060-check` で消せます。

## 手順5：プラグインがマーケットプレイスからインストールできることを確かめる

Claude Code（デスクトップアプリ、またはターミナルの `claude`）で行います。

1. **以前に ctxjev をインストールしたことがある場合**は、先に取り除きます。入力欄に `/plugin` と入力して Enter →「Installed」（インストール済み）の一覧から **ctxjev** を選び →「Uninstall」を選びます。（以前のものは `main` から入れた版で、同じ「0.6.0」という番号でも中身が古い可能性があるためです。）
2. 入力欄に次を入力して Enter を押します。すでに追加済みと表示された場合は、代わりに `/plugin marketplace update ctxjev-plugins` を実行します。

   ```
   /plugin marketplace add x96x64/ctxjev
   ```

3. 入力欄に `/plugin` と入力して Enter →「Discover」（探す）または「Marketplaces」から **ctxjev** を選び →「Install」を選びます。
4. インストール後、入力欄に `/ctxjev:status` と入力して Enter を押します。状態のレポート（目標や直近の実行結果）が表示されれば動いています。
5. `/plugin` の「Installed」で ctxjev の版が **0.6.0** と表示されることを確認します。ターミナルで `ls ~/.claude/plugins/cache/ctxjev-plugins/ctxjev/` を実行すると `0.6.0` というフォルダがあります（タグ `v0.6.0` から取得された印です）。

## 第6節：うまくいかなかったとき

| どこで | 何が起きたか | どうするか |
| --- | --- | --- |
| 手順1 | PR B の検査に赤い ✗ がある | マージしないでください。Claude Code に「PR B の CI が赤い」と伝えてください。原因を調べて直します |
| 手順2 | ワークフローが「pnpm test」「Eval gate」「Check version lockstep and pins」のどれかで止まった（何も公開されていない） | npm には何も出ていません。**PR B を取り消します**（下の「PR B の取り消し方」）。マーケットプレイスが、まだ無いタグ `v0.6.0` を指したままになるのを防ぐためです。その後、ワークフローの画面のリンクを Claude Code に渡して原因の調査を頼んでください |
| 手順2 | 「Publish ctxjev-core」などの公開ステップの途中で止まった（一部だけ公開された） | **npm の公開は取り消せず、同じ版の再公開もできません。** 自分で再実行はせず、ワークフローの画面のリンクを Claude Code に渡してください。残りのパッケージの公開方法を一緒に決めます |
| 手順2 | 最後の「Tag and create the GitHub Release」だけが失敗した（3つとも公開済み） | タグを手で作ります：リポジトリの右側「Releases」→「Draft a new release」→「Choose a tag」に `v0.6.0` と入力し「Create new tag: v0.6.0 on publish」を選ぶ →「Target」は `main` →「Release title」に `v0.6.0` →説明欄に CHANGELOG.md の「0.6.0」の節を貼り付け →「Publish release」 |
| 手順3 | 10分以上たっても npm が 0.6.0 にならない | 手順2のワークフローが全部緑かを確認し、緑なら Claude Code に相談してください |
| 手順4 | コマンドが失敗する、または結果が違う | 出力をそのままコピーして Claude Code に渡してください。0.6.0 自体に問題がある場合は、修正版（0.6.1）を出して直します（公開した版は取り消しません） |
| 手順5 | プラグインのインストールが失敗する | ① リポジトリの「Tags」にタグ `v0.6.0` があるか確認（無ければ手順2の最後の行の方法で作る）。② Claude Code が古い可能性があるので、ターミナルで `claude update` を実行してから再度試す。③ それでも失敗する場合は Claude Code に相談してください（マーケットプレイスの設定を `main` 配信に戻す PR を作れます） |

**PR B の取り消し方**（公開ワークフローが何も公開せずに失敗した場合）：

1. マージ済みの PR B のページを開きます。
2. ページ下部の **「Revert」** ボタンをクリックします。取り消し用の新しい PR が作られます。
3. その新しい PR で、手順1と同じように検査が4つとも緑になるのを待ち、**「Create a merge commit」** でマージします。
4. これで `main` は PR B をマージする前の状態（マーケットプレイスは `main` から配信、MCP の設定例は 0.5.0、README に「npm は 0.5.0」の注記）に戻ります。原因を直してから、手順1からやり直します。

Claude Code に「PR B を取り消す PR を作ってマージして」と頼むこともできます。
