## 4. カテゴリ別の詳細レビュー

### 4.1 Core functionality & correctness（中核機能と正しさ）13.5 / 15

**このツールの仕組み（用語の説明をかねて）**

- このリポジトリは **モノレポ**（複数のパッケージを1つの置き場で管理する形）で、4つのパッケージがあります。
  - `ctxjev-core`：中心の処理（ライブラリ）
  - `ctxjev-cli`：コマンドで使う道具（**CLI**＝文字を打って使うプログラム）
  - `ctxjev-mcp`：AI アプリから道具として呼べる窓口（**MCP**＝AI アプリが外部の道具を呼ぶための共通の決まり）
  - `ctxjev-claude`：Claude Code の追加部品（**プラグイン**）。**フック**（Claude Code が決まった場面で自動で動かす小さなプログラム）で動きます。
- 記録の各項目に点数を付け、「残す／短くする候補／削る」に分けます。点数の付け方（**採点方式**）は3つです。
  - `recency`：新しさだけ。CLI とライブラリの既定。つまり「古いものから消す」単純な切り捨てです。
  - `local`：目標の文とのキーワードの重なり。オフライン。プラグインの既定。
  - `jev`：Jev に判定させる。自分で選んだときだけ（MCP だけは既定が Jev）。
- **トークン**は、AI が文章を数える単位です。

**良い点（根拠）**

- **説明書どおりに動く。**
  - npm から公開版 0.7.1 を新しい一時フォルダに入れ、README の Quick Start をそのとおりに実行しました。出力は README と1バイトも違いませんでした（検証 E3）。
  - リポジトリ付属の照合スクリプト `scripts/check-readme-examples.mjs` でも、README の例 4/4 が一致しました（検証 B6）。
- **削る処理の約束が崩れない。**
  - Anthropic の会話形式（Claude の API に送る会話の形）では、次の約束があります。
    - ツールの呼び出し（`tool_use`）と結果（`tool_result`）は必ず一緒に消す
    - 最初のメッセージ、最新のやり取り、最後の数件は触らない
    - ユーザーの書いた文は既定で残す
  - 私が独自に書いた検査で、合成の会話21件 × 設定 576 通り＝**12,096 回**実行し、**違反は0件**でした（検証 B2）。
  - 「節約したトークン数」は、実行前後の数の差と**全件で完全に一致**しました。予算超過の印（`overBudget`）も全件で正しい値でした。
  - CLI でもサンプル8件 × 採点方式2つ × 設定12通り＝192 回で、違反 0、`analyze`（判定の表示）と `prune`（実際に削る）の数値は有効な 70 回すべてで一致しました（検証 B1）。

**問題点と根拠**

1. **削除の注記が、黙って付かないことがある（新発見・小〜中）。**
   - 削った場所には「ここで履歴を削りました。ファイルを読み直してください」という1行の注記（マーカー）が付く約束です。
   - ところが、注記を置ける「保護されていないユーザーのメッセージ」が無いと、注記を付けずに削ります（`packages/core/src/anthropicMessages.ts:352-358`）。コードのコメント（同 `:127-130`）には書かれていますが、結果にも CLI の表示にも「注記を付けなかった」という知らせがありません。
   - 例：`examples/sample-transcripts/anthropic-messages.json` を `--target-tokens 50` で削ると、8件中5件を消しますが注記は付きません（検証 B1）。
   - 頻度：既定の設定では 0〜6/42 件ですが、`--drop-user-text` と厳しい予算（10%）を組み合わせると **37/42 件**で注記が消えます（検証 B3）。たくさん削ったときほど注記が無くなる、という逆の効き方です。
2. **`prune` が `--goal` の上書きを出力ファイルに書き込む（小）。** `packages/cli/src/index.ts:335`・`:345` が `{ ...file, goal, … }` と書くため、元のファイルに無かった目標や、上書きした目標が出力に残ります（検証 B5）。README は「他の項目はそのまま書き戻す」と書いており、目標が書き換わることは書いていません。
3. **無言で進む小さな場面。**
   - Claude Code の記録（`.jsonl`＝1行に1つの JSON を並べた形式）の壊れた行は、警告なしに読み飛ばします（`packages/core/src/claudeCodeTranscript.ts:51-54`。意図的と注記あり）。重複した記録には警告を出すので、扱いが揃っていません。
   - 対応する呼び出しの無いツールの結果だけのメッセージは、項目 0 件として警告なしに通ります。
   - MCP のツールに未知の引数（例：`policy`）を渡すと、エラーにならず黙って捨てられます（検証 D1）。
   - `local` で全項目が同点（例：どれも目標と重ならない）のとき、全項目の関連度が 1（最大）と表示されます（`packages/core/src/percentile.ts:17`）。残す判断としては安全ですが、表示の意味としては誤解を招きます。
