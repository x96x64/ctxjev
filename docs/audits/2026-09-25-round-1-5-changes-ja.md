## 用語メモ（初出のみ）

- **テスト**：コードが期待どおりに動くかを自動で確かめる小さなプログラム。`pnpm test` で全部を実行します。
- **CI**：GitHub が変更のたびに自動で実行する検査（テスト、型チェック、文書の数値検査など）。
- **dist**：ソースから作った配布用のファイル。プラグインの dist はリポジトリに含めています。

- **ライブ確認**：本物の Jev の API を実際に呼ぶ確認（有料。ごく少額）。

## 3. 期待値を変えたテストと、弱めていない理由

削除したテストはありません。既存のテストの期待値を変えたのは次の場合だけで、どれも検査の強さは同じか強くなっています。

| テスト | 変更 | 弱めていない理由 |
| --- | --- | --- |
| `jevClient.test.ts`「asks one question per entry…」 | 質問の名前の期待を「項目の ID」から「`e0`, `e1`…」に | 仕様の変更そのもの（ID を送らない）。本文が順に正しく入っていることの検査を追加 |
| `jevClient.test.ts` の偽の Jev | 答えを「ID」ではなく「本文」で決めるように | 要求に ID が無くなったため。答えが正しい項目に戻ることは、本文で見分けて引き続き検査 |
| `anthropicMessages.test.ts` のツールの対のテスト | 採点を `local` から固定の点数に | 検査の対象（対が壊れないこと、同じ3件が消えること）は同じ。`local` の新しい挙動は `prune.test.ts` で別に検査 |
| `anthropicMessages.test.ts` の 15 万件のテスト | `protectLastTurn: false` を指定 | このテストの目的は「10 万件以上を消せること」。既定では会話全体が最新ターンになり何も消えないため。既定の挙動は新しいテスト群で検査 |
| 同じファイルの性質テスト | `protectLastTurn` を乱数でオン・オフ | オンのときに「最新ターンが変わらない」を検査に追加（強化） |
| `preCompact.test.ts` の2件 | `CTXJEV_SCORER=jev` を指定し、名前を変更 | 既定がオフラインになったため、Jev を選んだ場合の失敗時の動きを引き続き検査。注記に `CTXJEV_SCORER=jev` が含まれることの検査を追加。既定の動きは新しいテストで検査 |
| `select.live.test.ts` | 採点方式 `'jev'` を明示 | 既定が `'local'` になったため。ライブテストが Jev を測り続けるため |

## 4. `pnpm test` から除外したもの（`8b81ea6`）

- **除外したもの**：`packages/core` の `eval/fixtures/**` だけです（`packages/core/package.json` の `"test": "vitest run --exclude \"eval/fixtures/**\""`）。該当するのは、ラウンド2の課題形式の見本（`eval/fixtures/tasks/format2-demo/`）にある2つのファイルです。

  - どちらも `harness-selftest.mjs`（CI の `eval-harness`）が、本来の場所で実行して検査しています。
- **本物のテストの数は減っていません**：同じコードで、除外の前後を比べました（API キーなし、`TYPESAFE_BASE_URL` は閉じたローカルポート）。
